TCK Compatibility Dashboard for Drools

BAMOE Team · Private CI Dashboard · Task Summary
Problem

The BAMOE team was manually monitoring the upstream dmn-tck/tck repository for new PRs, hand-copying test cases locally, building Drools 999-SNAPSHOT from source, running tests, and fixing failures — all with no shared visibility, no automation, and no central tracking.

Solution

A private CI dashboard repo in the team's GitHub org that automates the entire workflow end-to-end and serves a live dashboard to the whole team via GitHub Pages.

Key Design Decisions
Private repo, not a fork
  • Lives in the team's GitHub org
  • Visible only to BAMOE team members
  • No manual syncing from upstream needed
  • CI fetches upstream directly via API
Drools built from source in CI
  • 999-SNAPSHOT is never published to any repo
  • Clones apache/incubator-kie-drools at HEAD
  • Maven cache keyed on Drools HEAD SHA
  • Cache hit: ~10 min · Cache miss: ~60 min
Test specific upstream PRs
  • Workflow can be triggered manually
  • Pass an upstream PR number as input
  • CI merges that PR branch on top of master
  • Dashboard shows which PR was tested
Dashboard auto-updates
  • Runs nightly at 02:00 UTC automatically
  • Commits results + HTML back to the repo
  • GitHub Pages serves the latest HTML
  • No manual steps needed after initial setup

Setup Steps (one-time)
1
Create private repo in your org and push this code to it.
2
Create a PAT with repo write scope and add it as secret DASHBOARD_PAT.
3
Enable GitHub Pages → branch main → folder /docs.
4
Trigger once manually via Actions → Run workflow. Dashboard goes live immediately after.
